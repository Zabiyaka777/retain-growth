# Retain Growth

## Архітектурні принципи

### Мультитенантність з дня 1
Проєкт будується як SaaS з мультитенантністю з самого початку, а не додається пізніше.
- Кожна таблиця лідів, тредів (threads) і credentials має колонку `org_id`.
- Будь-який запит до цих таблиць має бути scoped по `org_id` (через RLS-політики в Supabase та/або явний фільтр у коді) — без винятків "тимчасово для одного тенанта".
- Нові таблиці, що зберігають дані, прив'язані до клієнта/організації, за замовчуванням отримують `org_id` при проєктуванні схеми.

### Ізоляція Netlify Functions
Кожна Netlify Function — ізольований, stateless-обробник.
- Функції не діляться спільним in-memory станом між викликами чи між собою (жодних module-level кешів/лічильників, які мають "виживати" між запитами як джерело істини).
- Увесь стан, що має жити довше одного виклику, зберігається зовні (Supabase/БД, а не в пам'яті процесу функції).
- Одна функція не повинна покладатися на побічні ефекти виконання іншої функції в тому самому деплої.

## Стек
- Netlify Functions (Node/TypeScript)
- Supabase (Postgres + service_role для серверних операцій)
- Telegram Bot API (вебхук у `netlify/functions/telegram-webhook.ts`)

## Git-дисципліна для сесій
Над цією папкою паралельно працюють кілька сесій, і всі вони деплоять у той самий прод. Деплой викладає все, що лежить на диску, тож без комітів неможливо відрізнити свою правку від чужої.

- **Перед стартом роботи:** `git status`. Якщо там є чужі незакомічені зміни (з іншої сесії) — не займати їх, не правити й не комітити разом зі своїми. Повідомити користувачу і зупинитись, доки він не скаже, що робити.
- **Перед великою задачею:** дописати свій рядок у `.claude/CURRENT_WORK.md`, перед завершенням — прибрати його (формат описаний у самому файлі).
- **Перед кожним деплоєм:**
  1. `git add -A && git commit -m "<що зроблено, українською, коротко>"`
  2. `git log --oneline -5` — переконатись, що зверху саме твій коміт, а не чийсь, що встиг проскочити між твоїм комітом і деплоєм.
  3. Деплой.
- Ніякого деплою без коміту перед ним.
- **Лендінг (`retain-growth.ai`) деплоїти лише через `npm run deploy:landing`** — не вручну `netlify deploy`. Скрипт спершу викладає чернетку, перевіряє, що на ній немає жодної функції застосунку (двічі вони туди витікали через кеш/шлях функцій), і лише тоді публікує та перевіряє прод.
